LSR Grabber v6.1

Pulls LSR / Validation Error Report data straight into the Off-Spec Generator. v6 fixes the auto-read failures seen on locked-down machines — and when it still can’t, it tells you why instead of dying silently.

1 Install the bookmarklet

Make sure your Bookmarks bar is showing — Ctrl+Shift+B toggles it in Chrome.

↧  LSR Grabber v6
Drag this button up onto your bookmarks bar. Don’t click it here — it only works on a SAP LSR page.

2 Use it

  1. In SAP, open the LSR (or Validation Error Report) so the PDF is the page you’re on.
  2. Click LSR Grabber v6.1 on your bookmarks bar.
  3. It reads the PDF and opens the Off-Spec Generator in a new tab with the data loaded.
  4. If it can’t auto-read, a panel appears — use Pick PDF from disk to keep working, then Send to Dan to mail him the diagnostic (mail client opens pre-filled).

What changed from v4

+ v6.1 — manifest detection fixed
v4/v6 only recognized manifest numbers ending in JJK — it silently dropped NHWM-prefixed, FLE/WAS/VES/GBF/SMS/GREEN/DAT suffixes, and plain 7-digit manifests. Now format-agnostic. Validated against a real LSR: 11/11 manifests, 31/31 rows (v4 got 7 and 23).
+ credentialed fetch
The one weak line in v4 — getDocument({url}) — re-fetched the PDF without your SAP session cookie. v6 uses the same fetch(…,{credentials:'include'}) pattern that the Extract Samples tool already proves works on Tradebe machines.
+ diagnostic that talks
A failed read now reports what came back — an auth/login page, an HTTP 401/403, a 30s timeout — instead of v4’s silent Error:. Includes a one-click Send to Dan mailto. Stays in until the rollout is stable.
= parser untouched
The whole v4 coordinate-grid parser, the 14 column anchors, and the #bm= hand-off to the Off-Spec Generator are byte-for-byte unchanged.
+ disk-pick fallback
v4 had none — one failed fetch and it was dead. v6 always offers “Pick PDF from disk” as a zero-network safety net.
− no external loader
The v5 design that fetched the extractor from ec-receiving.web.app is gone — that’s what introduced the CSP / web-filter failures. v6 is fully self-contained. (PDF.js still loads from cdnjs, exactly as v4 did.)
Honest caveat: this targets the failure we can see in v4’s code and removes every v5-specific failure mode — but it can’t be guaranteed on a machine that can’t be tested. If your boss’s machine still fails, the diagnostic panel is now built to tell us exactly where, so the next fix isn’t a guess.
